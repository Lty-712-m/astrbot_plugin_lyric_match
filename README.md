# 歌词识别（astrbot_plugin_lyric_match）

当主人说 / 哼出一句歌词时，让 Bot 认出这是哪首歌，并做出「惊喜、接下一句、我也喜欢这首」的反应。

插件在消息送进大模型**之前**介入（`@filter.on_llm_request`），分两段判断：

1. **这一段像不像在念歌词？** —— 纯规则预筛，不调大模型，几乎零成本。
   看长度、日常词占比、句式（短句 / 少标点 / 句尾成韵）、抒情词覆盖率、第二人称「你」+ 抒情词等。
2. **像的话，是哪首歌？** —— 到本地歌词库做 2-gram 倒排索引 + 模糊匹配，
   置信度 ≥ 阈值（默认 0.85）才算确认。

两段都通过，才在 `system_prompt` 末尾追加：

```
【歌词识别】主人刚才念的像是《歌名》的歌词：「匹配到的原句」。这首歌紧接着的下一句是：「下一句」。你要立刻认出来并惊喜地接话；可以顺势哼下一句，但必须用上面给出的这一句，不要自己编，也不要整段背。
```

**插件本身不附带任何歌词**（版权原因），需要你自己准备歌词文件放进 `lyrics/`。

## 安装

### 方式一：WebUI 上传 zip（推荐）

1. 把整个 `astrbot_plugin_lyric_match` 文件夹压缩成 zip（zip 里应当是 `astrbot_plugin_lyric_match/…` 这一层）。
2. 打开 AstrBot WebUI →「插件」→「安装插件」→ 上传 zip。
3. 装好后在插件列表里启用「歌词识别」。

### 方式二：手动解压

把 `astrbot_plugin_lyric_match` 整个文件夹放到 AstrBot 的插件目录：

```
AstrBot/data/plugins/astrbot_plugin_lyric_match/
```

然后重启 AstrBot，或在 WebUI 插件页点「重载插件」。

> 兼容：AstrBot `>=4.27.0,<5`（在 4.29 上开发验证），平台 `aiocqhttp`。
> 无第三方 Python 依赖，`requirements.txt` 里只有说明。

## 可视化歌词管理（插件页面）

装好插件后，在 WebUI 里打开：

```
控制台 → 插件 → 歌词识别 → 歌词管理
```

页面上可以：

- **查看**当前 `lyrics/` 下的文件（文件名、大小、首数、句数、修改时间、解析错误）；
- **上传**歌词文件：点「上传歌词文件」，支持一次选多个 `.txt` / `.json` / `.lrc`，单文件 ≤ 5 MB；
- **删除**单个歌词文件（会弹确认）；
- **重新加载**歌词库，相当于在聊天里发 `/lyric reload`；
- 顶部实时显示歌曲数 / 歌词句数 / 2-gram 索引数 / 文件数。

上传成功后会自动重载歌词库，并提示「已上传 N 个文件，当前 M 首」。
歌词库为空时页面会给出格式示例和操作指引。

> 安全：页面只能写入插件自己的 `lyrics/` 目录，文件名会清洗成 basename，
> 只允许 `.txt` / `.json` / `.lrc`，单文件上限 5 MB，`README.txt` 等说明文件不可删除。

## 准备歌词库

插件目录下有个 `lyrics/` 文件夹，把歌词文件放进去即可，支持 `.txt`、`.json`、`.lrc`，也支持子目录。

### txt 格式（和常见的「歌名 + 一句一行」一样）

```
《歌名》（歌手）
  第一句歌词
  第二句歌词
  第三句歌词
```

- 歌名单独一行，用 `《》` 包起来；后面的（歌手）可省略。
- 每行一句；空行、`#` / `//` 注释行会被忽略。
- 「作词：…」「作曲：…」这类制作信息行会自动跳过。
- 一个文件里可以放多首，每首以新的 `《歌名》` 行开始。

### json 格式

```json
{
  "songs": [
    {"title": "歌名", "lines": ["第一句歌词", "第二句歌词"]}
  ]
}
```

根节点是 `{"songs": [...]}` 或直接的 `[...]` 数组都行；`lines` 也兼容 `snippet` / `lyrics` 字段。

### lrc 格式

直接上传 `.lrc` 即可：

```
[ti:歌名]
[00:12.34]第一句歌词
[00:16.80][00:20.10]第二句歌词（副歌会重复）
```

- 歌名优先取 `[ti:…]`，没有就用文件名（会去掉开头的 `01.` 这类序号）；
- 时间戳（包括一行多个时间戳）会被自动剥掉；
- `[ar:]` `[al:]` `[by:]` 等元数据行会被跳过。

> 详细格式见 `lyrics/README.txt`。

### 加载 / 热重载

- 插件启动时会全量扫描 `lyrics/`。
- 放进新文件后不用重启，聊天里发 **`/lyric reload`** 即可热重载。
- 想从别的目录读歌词：在插件配置里填「额外歌词目录」，多个目录用英文分号 `;` 分隔。

## 指令

| 指令 | 作用 |
| --- | --- |
| `/lyric reload` | 重新加载 `lyrics/` 下的歌词库（默认仅管理员） |
| `/lyric list` | 查看已经加载的歌及句数 |
| `/lyric stat` | 查看歌词库统计（歌曲数 / 句数 / 索引数 / 目录 / 解析错误） |

普通聊天里不需要任何指令：把歌词**单独发一条**就会自动识别。

## 连续接唱

如果主人一句接一句地连着唱，每次都「哇这是《X》」会很吵。插件带一个状态机：

- 第一次命中 → **惊喜模式**：认出歌名 + 接下一句
- 之后在 `sequence_window`（默认 180 秒）内再命中 → **接唱模式**：直接接下一句，不再惊讶、不再重复歌名
- **不限同一首**：连着唱另一首也算接唱
- 停超过窗口时长后，回到惊喜模式

两个模板都可以在配置里改：`inject_template`（惊喜）和 `continue_template`（接唱）。

## 配置项

在 AstrBot WebUI → 插件 →「歌词识别」→ 配置里修改。

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | 开 | 总开关 |
| `similarity_threshold` | `0.85` | 第二段确认阈值：歌词库匹配置信度达到它才注入 |
| `min_length` | `8` | 最小长度（归一化后字符数），太短的消息直接跳过 |
| `private_only` | 关 | 只在私聊生效 |
| `inject_template` | 见上 | 注入模板，支持 `{title}` `{line}` `{next}` `{score}` |
| `extra_lyrics_dir` | 空 | 额外歌词目录，多个用 `;` 分隔 |
| `candidate_k` | `20` | 先用 2-gram 取前 N 句候选，再逐一算相似度 |
| `rule_threshold` | `0.5` | 第一段「像不像歌词」的规则得分门槛 |
| `debug_log` | 关 | 把预筛得分、候选歌名、相似度写进日志，排查误判用 |
| `admin_only` | 开 | `/lyric reload` 仅管理员可用 |

### 自定义注入模板

模板里可以用这些占位符：

- `{title}` —— 歌名
- `{line}` —— 匹配到的原句
- `{next}` —— 原句的下一句（没有则为空）
- `{score}` —— 置信度，如 `0.93`

例如想让 Bot 直接接下一句：

```
【歌词识别】这是《{title}》的「{line}」，下一句是「{next}」。认出来后惊喜地接下一句，别背整段。
```

## 误判 / 漏识别怎么调

先开 `debug_log`，看 AstrBot 日志里是哪一段没过：

**误判太多**（普通聊天被当成歌词）：

1. 把 `similarity_threshold` 从 `0.85` 调到 `0.88 ~ 0.95`（最有效）。
2. 把 `rule_threshold` 从 `0.5` 调到 `0.6 ~ 0.7`。
3. 把 `min_length` 从 `8` 调大（比如 `10`），短句不再参与识别。
4. 群聊里太吵的话，打开 `private_only`。
5. 实在不行直接关 `enabled`。

**漏识别太多**（明明是歌词却没反应）：

1. 把 `similarity_threshold` 降到 `0.78 ~ 0.82`。
2. 把 `rule_threshold` 降到 `0.4 ~ 0.45`。
3. 检查 `/lyric stat`：歌词库里到底有没有这首歌、有没有解析失败。
4. 确认歌词是**单独发的一条**，没有夹在长句里。
5. 歌词库很大时把 `candidate_k` 调高（如 `40`），避免真句没进候选。

**这就是为什么建议单独发一条歌词**：夹在长句里时，规则预筛和相似度都会被稀释，容易漏。

**为什么不建议发 rap 歌词**：rap 的断句、用词和正常聊天非常接近（大量口语、没有明显韵脚句式），
第一段规则预筛很难把它和聊天区分开，误判率明显高于抒情歌。

## 工作方式（简）

```
消息进入
  └─ on_llm_request
       ├─ 规则预筛（detector.py）
       │    长度 / 日常词占比 / 问号 / 链接 / 表情 / 句式 / 抒情词 / 韵脚
       │    不通过 → 直接放行，不注入
       └─ 歌词库匹配（lyrics_lib.py）
            2-gram 倒排索引取共享 2-gram 最多的前 20 句
            → difflib 相似度 + 最长公共片段
            → 最高分 ≥ 0.85 → 注入 system_prompt
```

归一化会去掉标点、空格、表情，只保留汉字 / 假名 / 字母 / 数字并转小写，
所以「如今等闲飘零」和「如今，等闲飘零！」会被当成同一句。

## 常见问题

**Q：为什么插件里一首歌都没有？**
A：版权原因，插件不打包歌词。需要你自己准备歌词文件放进 `lyrics/`，再 `/lyric reload`。

**Q：支持 LRC 吗？**
A：支持。直接把 `.lrc` 文件放进 `lyrics/`（或从「歌词管理」页面上传）即可，时间戳会被自动去掉；
歌名优先取 `[ti:…]`，没有就用文件名。纯音乐标记行建议先清理。

**Q：会把我发的歌词存下来吗？**
A：不会。插件只读歌词文件，不写任何用户消息，也不联网。

**Q：Bot 会整段背歌词吗？**
A：默认模板明确要求「别整段背」，只接一句。想更严格可以自己改 `inject_template`。
