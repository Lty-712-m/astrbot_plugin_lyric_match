歌词库说明
==========

插件本身不附带任何歌词，请自己把歌词文件放进本目录（lyrics/）。
然后在聊天里发 /lyric reload 重新加载，或者在插件的「歌词管理」页面点「重新加载歌词库」。

支持 txt / json / lrc 三种文件格式，可混用，也会扫描子目录。


一、txt 格式（一句一行）
------------------------

《歌名》（歌手）
  第一句歌词
  第二句歌词
  第三句歌词

说明：
- 歌名必须单独占一行，用 《》 包起来；
- 歌名后面的（歌手）可写可不写；
- 下面每行一句歌词，空行会被忽略；
- 以 # 或 // 开头的行是注释，会被跳过；
- 「作词：xxx」「作曲：xxx」这类制作信息行会自动忽略；
- 一个 txt 里可以放很多首歌，每首以新的《歌名》行开始。

示例（把示例歌词换成你自己的内容）：

《示例歌曲》（示例歌手）
  这是第一句示例歌词
  这是第二句示例歌词
  这是第三句示例歌词


二、json 格式
-------------

{
  "songs": [
    {
      "title": "歌名",
      "lines": [
        "第一句歌词",
        "第二句歌词"
      ]
    }
  ]
}

说明：
- 根节点可以是 {"songs": [...]}，也可以直接是 [...] 数组；
- 单首歌也可以只写一个对象 {"title": "...", "lines": [...]}；
- title 必填；lines 必填，也兼容 snippet / lyrics 字段；
- artists 可选，只用于 /lyric list 展示。


三、lrc 格式
------------

[ti:歌名]
[00:12.34]第一句歌词
[00:16.80]第二句歌词

说明：
- 歌名优先取 [ti:...]，没有就用文件名（自动去掉开头的 01. 这类序号）；
- 时间戳会被剥掉，一行多个时间戳也支持；
- [ar:] [al:] [by:] 等元数据行会被跳过；
- 连续重复的同一句只保留一条。


四、注意事项
------------

- 文件名任意，扩展名必须是 .txt / .json / .lrc；
- 文件统一用 UTF-8 编码保存；
- 歌名相同的文件只会加载第一首（先加载到的优先）；
- 单文件请控制在 5 MB 以内（页面上传限制）；
- 想确认加载结果，发 /lyric stat 或 /lyric list；
- 也可以打开 WebUI「控制台 → 插件 → 歌词识别 → 歌词管理」，
  直接上传 / 删除歌词文件，上传后会自动重载。
